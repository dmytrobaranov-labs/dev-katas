# Middle .NET Developer Technical Practicum

Six practicums and a set of katas that prepare you for a technical interview for a Middle .NET Developer role: delegates, async, ASP.NET Core, EF Core, SQL Server, finding bugs in other people's code and typical live-coding tasks. The practicums' own estimates add up to 69–86 blocks of 50 minutes; a realistic first pass takes 92–122 blocks, or 77–102 hours.

Parts are added here one at a time. The table in [Contents and time](#contents-and-time) shows which parts are available.

## How it was made

The text, tasks and code were generated with AI (Claude). A human, the author, is checking them by working through every level: writing the tests, running them and reading the code and the explanations. Not everything has been checked yet, so each part and each level carries a status line right under its heading.

| Status | Meaning |
| --- | --- |
| `AI-generated · To verify` | Generated by AI; no human has worked through it yet. Expect mistakes. |
| `AI-generated · Human-verified` | Worked through end to end: tests green, code and text checked. |
| `AI-generated · Human-verified up to <task, test>` | Worked through partly, for example `up to task C, test 3`. Everything after that point is still to verify. |

Found a mistake? Please open an issue.

## Who it is for

- Developers preparing for Middle .NET interviews who want to close the topics that come up most often.
- Especially those who have read and debugged a lot of other people's code (support, maintenance, troubleshooting) but have designed little themselves. The practicum turns “I recognise this in code” into “I can write it and explain it”.
- Not for C# beginners: the language syntax is not explained here; it comes from the books listed in each part.

## Prerequisites

- **C#:** classes, interfaces, properties, exceptions, collections, using generics, reading LINQ queries.
- **Testing:** basic xUnit (`[Fact]`, `[Theory]`, `Assert`). If you don't have it yet, one evening with the docs and a palindrome kata is enough.
- **Tools:** .NET SDK 8 or later (the practicum is tested on .NET 10), Visual Studio or Rider, git, `dotnet test` from the command line.
- **HTTP:** methods, status codes, headers. Needed for the ASP.NET Core part.
- **SQL:** basic `SELECT`, `JOIN`, `GROUP BY`; SQL Server Developer Edition or a Docker image, plus SSMS or Azure Data Studio. Needed for the SQL Server part.
- **English:** reading documentation. Interview questions in every part are in English.

## Project setup

One solution for the whole practicum and a pair of projects per part: code and tests. Each level's tasks live in their own folder.

```
PracticeTdd/
    PracticeTdd.slnx
    Delegates/              class library
        Level0/
        Level1/ ...
    Delegates.Tests/        xUnit, references Delegates
        Level0/
        Level1/ ...
```

Commands to get started:

```
dotnet new sln -n PracticeTdd
dotnet new classlib -n Delegates
dotnet new xunit -n Delegates.Tests
dotnet sln add Delegates Delegates.Tests
dotnet add Delegates.Tests reference Delegates
dotnet new gitignore
git init
git add .
git commit -m "Initial state of TDD practice"
```

For the next parts, add the same kind of project pairs to the same solution, for example `Async` and `Async.Tests`.

Order: delegates, then async, then ASP.NET Core, then EF Core, since each part builds on the previous one. The bugs in “Find the bug” are best taken one at a time after the matching part (the bug map shows the link) and on days when you don't feel like writing code from scratch.

## How to study

- **50-minute blocks** with a 10-minute break. Phone in another room, one practicum part per block.
- **Level cycle:** read the chapter, close the book, answer the “Understand” questions in writing, then red test, minimal code, green, refactor. Open the reference solution only after your tests are green.
- **Demonstration tests start red too.** Some tests only show how the language behaves, and the code needs no change. Still get a red run first: either write a prediction test (a naive name and assert, red, then fix both), or break the condition temporarily. If you change what an assert means, rename the test in the same step.
- **First pass with hints.** If you can't work it out yourself the first time, take ready-made code step by step, but by the rules: first the test and a red run, then the code with a short “why”; type the code by hand, don't paste it. A day or two later, redo the level from scratch without hints: only the second pass shows what has stuck.
- **Spaced repetition.** A level is done when, the next day, you can write its exercise from memory in 15–20 minutes. Repeat it a week later. Anything you forgot goes onto flashcards.
- **Interleaving.** After two blocks of one part, do a block of another, for example SQL Server. You get less tired and remember more.
- **Explain it out loud (Feynman).** At the end of a level, explain the topic in 2 minutes as if to a junior. Answer the interview questions in English and record yourself: it prepares you for both the technical and the spoken part of the interview.
- **Commit after every green step.** Use a message like `Level0 C: ...`: the level, the task and what was done. The repository history shows your progress step by step and doubles as a portfolio.
- **Tick the checklists** at the end of each level (in your own copy), so you can see what is done and what is due for review.

## Working through it with an AI assistant

The practicum is written so that you can go through it on your own or with an AI assistant as a tutor. Paste a prompt like this at the start of a session:

```text
I'm working through the Middle .NET Developer Technical Practicum.
We're on Part <part>, level <level>, task <task>. Work with me like this:
- One step at a time: first the test; I run it and paste the red output.
  Then the code that makes it green, with a short "why": what breaks if done differently.
- On the first pass, give me ready code, not just hints. I type it by hand.
- You can't see my disk: I paste code and the output of dotnet test, git status, git log.
- After each green step, suggest a commit message like "Level0 C: ...".
- The practicum was generated by AI. If something in it looks wrong, say so.
```
